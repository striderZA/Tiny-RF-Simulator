# Agent subsystem — AGENTS.md

## Purpose

Provide the UI-independent protocol and integration boundary for agent clients.

## Ownership

- `mcp/` owns `simulator::mcp_adapter`: the transport-neutral MCP session, legacy initialization-era and stateless modern protocol handling, tools discovery/calls, ordered argument transfer, and cancellation handoff.
- `mcp/` also owns `GuiLink`, the lazy `rfsim-agent/1` client transport: it reads and authenticates the private endpoint, relays tool calls with ordered arguments, and drops/retries failed connections. It depends only on `agent_protocol` and threads and never edits simulator state.
- `mcp_bridge.{h,cpp}` owns `runBridge`, and `mcp/src/main.cpp` owns the `rf-sim-mcp` CLI and process entry point. The bridge transports MCP JSON-RPC over standard input/output and relays calls through `GuiLink`; it does not own simulator behavior. Release archives package it beside the GUI executable as `rf-sim-mcp` or `rf-sim-mcp.exe`.
- Agent-facing circuit edits belong in the API layer and must go through `EditorCommands`; protocol code does not edit simulator state.
- `api/` owns the UI-free `simulator::agent_api` core and circuit/component/type/library query tools, `circuit_edit`, and measurement tools `measure_port` and `network_analyzer_sweep`; it validates ordered-JSON arguments, reports epoch-aware results, and attempts one activity recording per call. Port measurements recompute the live runtime before reading; analyzer project settings are checkpointed only when changed. Unavailable/non-finite numeric measurements are JSON `null`, and sweep settings echo the engine-clamped point count. Sink failures are logged without replacing computed results.
- `api/` also owns the read-only `data_file_read` tool: a bounded S-parameter summary of a component's `sparam_filepath` or a library part's first `s_parameters` data file. It takes no paths and never writes. The shared library-part lookup lives in `agent_library` (`matchingParts`, `partCandidates`), and `findById`, `staleMeasurementEpochError`, `AgentEndpoint`, and `resolveOutputEndpoint` are declared in `agent_tools.h`, so each tool uses one copy.
- `api/` also owns `test_flow_run`: a parametric sweep of component `serialize()` paths, run through `RunFlowWithinBoundary()` (`test_flow/`), which restores the circuit once after the sweep. A run that restores cleanly leaves the project unmodified; a restore failure marks it modified. Its run seam, `AgentApi::setFlowRunBoundary()`, defaults to that boundary and exists for tests. A restore failure latches the tool: later calls return `INTERNAL` with the reload hint and run nothing until `noteProjectReplaced()` clears the latch.
- `api/` also owns `receiver_measure`: a receiver output-power and IIP3 sweep between two output ports. `AgentApi` owns one `ReceiverPerformanceMeasurementEngine` (`m_receiver_engine`), built from the context's runtime graph and const chain host and never shared with the app's panel engine. Each call runs one bounded engine `update()`, so the caller repeats it while `in_progress` is true. Endpoints resolve through the shared `resolveOutputEndpoint`, the same resolver `measure_port` and `network_analyzer_sweep` use. Unavailable values encode as `null`, and the tool is read-only: no checkpoint and no dirty mark.
- `api/` also owns `AgentServer`: it binds only an ephemeral loopback listener, owns endpoint/token cleanup, and allows one authenticated client. The listener thread handles socket framing and validated envelopes only, sharing inbox/outbox/status through a mutex; `pump()` on the caller thread alone checks modal state and invokes the executor. The pump preserves FIFO order, observes its configured budget between calls, and progresses at least one eligible call when work is queued. Server writes use a five-second whole-frame deadline.
- AgentServer checks each fully serialized JSON-RPC reply, including its id and duplicated `text`, against the 1 MiB cap. Oversized tool results become `INTERNAL` with the current epoch and message `Agent tool result exceeds the 1 MiB protocol limit`; if the fallback plus echoed id cannot fit, close/drop the connection.
- A call parks while a modal is open and receives `BUSY` once a dialog has stayed open for `park_timeout` (30 s). The park clock starts when the pump first sees the dialog open and resets whenever the pump sees it closed, so a closed dialog releases parked calls at the next pump and each reopened dialog starts a fresh clock.
- Agent v1 does not initiate file operations. It may read data files already referenced by a component or library part.

## Local Contracts

- `runBridge` reads bytes on a reader thread through `AgentLineReader`, scans framing incrementally, processes all `McpSession` state on a separate session thread, and dispatches queued calls serially in arrival order on one caller thread. Per-call client identity is captured on the session thread; an identity transition (including to an empty modern identity) replaces `GuiLink` before the next call. Cancellation suppresses only the matching MCP reply, never GUI-side work. One serialized writer emits and flushes each JSON-RPC message. Client identity fields escape control characters in stderr logs; unexpected call exceptions are diagnosed on stderr but return generic `INTERNAL` without exposing exception details. EOF stops input, drains queued calls, then returns.
- `rf-sim-mcp` accepts `--endpoint <file>`, `--version`, and `--help`; on Windows it sets stdin/stdout to binary mode before transport. The endpoint override is used as supplied; without one, the bridge derives the per-install endpoint file from `defaultAgentEndpointDirectory()`, `agentInstallKey(exe_dir)`, and `agentEndpointFileName()`. MCP discovery and `tools/list` do not require a reachable GUI.
- `simulator::agent_protocol` exposes only its own public headers, `nlohmann::json`, and standard C++; it must not include or link simulator or UI dependencies. On Windows it defines `NOMINMAX` and `WIN32_LEAN_AND_MEAN`; socket and existing platform libraries are linked only on Windows.
- The wire identifier is `rfsim-agent/1`. Messages are one JSON value per newline-delimited line, capped at 1 MiB; one trailing CR is stripped. An oversized line is reported once and discarded through its newline before parsing resumes.
- Messages nest at most `kAgentMaxJsonDepth` (64) containers. `agentJsonDepthWithin()` checks this iteratively before any recursive copy or dump: the bridge refuses a deeper line with `-32600` (echoing only a scalar id, and staying silent for a valid notification), `GuiLink` refuses deeper arguments with `INVALID_ARGUMENT` before connecting, and the GUI refuses a deeper call with `INVALID_ARGUMENT`.
- `AgentListener` binds an ephemeral IPv4 port on `127.0.0.1` only; `connectAgentLoopback()` also targets only that address. Windows initializes Winsock once through a function-local static and sets `SO_EXCLUSIVEADDRUSE` before bind. `accept(timeout)` remains deadline-bounded across transient readiness changes and returns blocking channels.
- The GUI-side listener and each accepted channel are close-on-exec: Linux creates them with `SOCK_CLOEXEC`/`accept4`; other POSIX systems set `FD_CLOEXEC` right after creation or accept (a short window against a concurrent fork); Windows sockets are not inherited because the runner's `CreateProcessW` passes `bInheritHandles = FALSE`. The client socket from `connectAgentLoopback()` is not close-on-exec; it exists only in the bridge process.
- A Windows connect wait watches the exception set as well as the write set, because Winsock reports a refused nonblocking connect there. `connectAgentLoopback()` therefore reports the `SO_ERROR` cause (for example `connect loopback failed with Winsock error 10061`) once the OS reports it, instead of `connect loopback timed out` at the deadline.
- `AgentChannel` is move-only and owns its socket plus `AgentLineReader`. Reads return `Line`, `Timeout`, `Closed`, `Oversized`, or `Error`, with timeout bounded across the whole wait; writes reject embedded LF, append one LF, and send all bytes. The timeout-bounded write overload shares one deadline across partial sends and closes the channel when a frame cannot finish. POSIX writes suppress SIGPIPE using `MSG_NOSIGNAL` or `SO_NOSIGPIPE`; unsupported POSIX targets fail clearly.
- Error names are `UPPER_SNAKE`. Tool errors use `{epoch, error: {code, message, hint?, op_index?, details?}}`; absent optional fields are omitted and absent epochs are JSON `null`. JSON-RPC agent errors use `-32000` and put the agent error name in `data.code`.
- API success and error results carry the current epoch at top level; `STALE_EPOCH.details.epoch` is the current epoch. Details include `cause` when known and `undone` summaries when the cause is `reverted`; each tool retains its existing stale-message wording. Keep every v1 tool's success schema aligned with this epoch rule.
- Measurement endpoint fields/types and negative indices return `INVALID_ARGUMENT`; unresolved component IDs or output-port indices return `NOT_FOUND`. `measure_port.trace` is an object of parallel `frequencies_Hz` and `noise_dBm_per_Hz` arrays.
- Non-finite numbers encode as JSON `null`; output schemas must permit `null` for numeric fields that can be unavailable or non-finite. The static catalog has deterministic v1 order and shared input/output schemas; tool behavior is added through the API layer. Within a `catalog_version`, changes are additive; removing or retyping a field or tool requires a version increment.
- `component_types` reads the registered type order and defaults/ports through per-`AgentApi` scratch graph, view, and component-registry state; each type engine is created once and reused only for discovery metadata.
- `library_search` matches query substrings case-insensitively across part number, manufacturer, and description, filters by type, sorts by `(type, part_number)`, and counts all matches before applying its bounded result limit. Type parameter metadata uses `boolean` for Boolean state fields.
- Library-part resolution for `circuit_edit` and `data_file_read` returns at most the first five matches for `UNKNOWN_PART` and `AMBIGUOUS_PART`, in deterministic order; ambiguous matches are sorted by `(part_number, type, manufacturer)`.
- `test_flow_run` checks, in order: epoch (`STALE_EPOCH`), the restore latch (`INTERNAL`), argument shape (`INVALID_ARGUMENT` at the offending path), duplicate condition and measurement targets, and a row product above 1000 (`INVALID_ARGUMENT` with `details.requested` and `details.limit`). All of these run before the seam is called. `FlowErrorCode` maps to `NOT_FOUND` for an unknown component or port, `PARAM_REJECTED` for a path the component cannot take, `INVALID_ARGUMENT` for metric and shape codes, and `INTERNAL` for deserialize and cycle failures.
- `receiver_measure` checks, in order: epoch first (`STALE_EPOCH` for a stale value; `INVALID_ARGUMENT` at `/epoch` for a missing, non-integer, or negative one), then unknown arguments and shape (`INVALID_ARGUMENT` at the path: non-finite numbers, a `start_Hz` not below `stop_Hz`, `points` outside 2–401, and an `iip3` object whose spacing and step are not positive, whose start exceeds its stop, or whose level count is invalid, reported at `/iip3`), then endpoints (`INVALID_ARGUMENT` when malformed, `NOT_FOUND` when unknown), then `findMeasurementChainPath`, where an absent path or one with fewer than two components is `NO_MEASUREMENT` with `details.reason` `NO_PATH`, the same reason `network_analyzer_sweep` uses.
- `simulator::agent_api` links the protocol, UI-free editor services, analyzer/measurement engines, and threads only. It must not link `simulator::app`, ImGui, ImPlot, ImNodes, or GLFW. Circuit edits remain routed through `EditorCommands`; the API reaches application behavior only through `IAgentHost`.
- `circuit_edit` accepts 1–64 ordered operations at the current epoch. References are call-local and become available after their add; processing stops at the first error, preserving and committing an applied prefix, while a failure before any applied op discards the checkpoint.
- Keep `circuit_edit`'s API result and protocol schema aligned, including `applied[].also_changed` records shaped as `{path, old_value, new_value}`. Log rollback-failure diagnostics locally without exposing them in client-facing errors.
- Placement is app-host work: report only newly added nodes, preserve explicit positions, and derive automatic columns from dependencies among added nodes (existing nodes do not add depth).
- Session tokens use 32 OS-CSPRNG bytes encoded as 64 lowercase hexadecimal characters; generation fails closed without fallback entropy. Equal-length tokens are compared across every byte with an XOR accumulator; unequal lengths are rejected.
- Endpoint files are named `agent-endpoint-<install>.json`, where `<install>` is the 16-lowercase-hex FNV-1a of the weakly canonical executable directory (lowercased before UTF-8 encoding on Windows). The POSIX directory and file are current-user-owned with modes 0700 and 0600; Windows uses protected current-user-only DACLs (`D:P(A;OICI;FA;;;<SID>)` for directories, `D:P(A;;FA;;;<SID>)` for files).
- POSIX endpoint writes and token-gated removals hold the same exclusive advisory `flock` on the parent directory across temporary-file replacement and identity/token-checked unlink; Windows retains handle-based behavior.
- Never expose extension trust grants/revocations, external-tool execution, component-library authoring, or `.rflib` import/export to agents.
- Any listener thread under this subsystem may share only the mutex-protected inbox, outbox, connection status, and pump-refreshed epoch snapshot with the UI thread. It must not touch simulator engines, graph state, or UI objects.

## Work Guidance

Keep protocol code transport-neutral and small. Put simulator integration behind the agent API and app-owned host interfaces; preserve the target's dependency boundary.
