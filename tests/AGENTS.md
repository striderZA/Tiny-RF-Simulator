# Tests - AGENTS.md

## Purpose

Own the Catch2 v3.4.0 unit test suite and ImGui test engine UI tests. Verify all DSP engines, node graph operations, touchstone parser, and application components produce correct results. Prevent regressions across the modular build.

## Ownership

- **test_main.cpp** — Catch2 test runner (Catch2::Catch2WithMain linked)
- **test_*.cpp** — Per-module test files, one per engine/component under test
- **test_pfb_filter_design.cpp** — standalone executable: real-prototype core + metric tests and PFB engine flat-noise/tone-weight regressions (kept out of the main `tests` binary for the MinGW registration ceiling)

## Local Contracts

- All tests use Catch2 v3 `TEST_CASE` / `SECTION` macros
- Floating-point comparisons use `Catch::Approx` from `<catch2/catch_approx.hpp>`
- Benchmark cases use `Catch::Benchmark::BENCHMARK` from `<catch2/benchmark/catch_benchmark_all.hpp>`
- Test files are named `test_<component>.cpp` matching the module name
- Build via `cmake --build build && ctest --test-dir build` or direct `build/bin/tests`
- Adding a new test file? Register it in `tests/CMakeLists.txt` via `add_standalone_test(test_<name> SOURCES test_<name>.cpp LIBS ...)` (the standard helper; preferred for new coverage — see the MinGW ceiling below). Add to the main `tests` binary's `TEST_SOURCES` only for a pure extension of an existing component already compiled into it.
- **MinGW-w64 test-registration ceiling:** this toolchain silently drops any `TEST_CASE` registered beyond the ~223 already linked into the main `tests` executable (verified 2026-08-09; the release.yml Windows jobs enforce the 223 floor with a `--list-tests` count guard). Do not add new `TEST_CASE`s to `test_main.cpp` or any file already compiled into the `tests` target — give the new coverage its own standalone executable instead (`add_executable(test_<name> test_<name>.cpp)` + `target_link_libraries` + `add_test`, following `test_attenuator`, `test_combiner`, `test_network_analyzer`, `test_component_authoring`, `test_tutorial_state`, `test_extensions`, `test_issue37_pfb_input_removal`, `test_issue70_pfb_reconnect`, `test_issue42_multi_output`, `test_component_dispatch`, `test_signal_domain`, `test_path_containment`, and `test_issue48_json_loader`), and run it directly (`build/bin/test_<name>.exe`) rather than relying on `ctest`. `test_issue48_json_loader` covers malformed project/library input via `TEST_CASE`s in its own standalone executable, outside the main `tests` registration ceiling, so it must be run directly (`build/bin/test_issue48_json_loader.exe`).
- Platform-specific tests (e.g., Windows-only session state) are gated with `#ifdef WIN32` in CMakeLists.txt
- **Scratch paths must be unique across processes, not just across calls.** `catch_discover_tests(tests)` registers one CTest entry per `TEST_CASE`, so under `ctest -jN` several cases run as separate processes at once and a `static` counter restarts at 0 in each of them. Resolve scratch paths under `temp_directory_path()` and tag each name with `test_temp_paths::processTag()` (`tests/test_temp_paths.h`), plus a counter where one process writes several files: the tag is what makes the name unique whichever way the case runs, while a relative name lands in the checkout for a standalone executable (`WORKING_DIRECTORY` is the source tree) or in `build/tests` for a main-binary entry. Converted to that form: `test_component_library`, `test_component_dispatch`, `test_issue116_collapsed_groups`, `test_issue70_pfb_reconnect` and `test_rf_switch_project`. A `random_device`-derived name is not a substitute: it is only *probabilistically* unique, and a collision clobbers the other process's file rather than failing loudly. The older fixed-name `<temp>/rfsim_ext_*` fixtures are safe only because exactly one `TEST_CASE` owns each name.
- **Exe-relative app state is shared by every test executable in `build/bin`.** `SessionState` derives `<exe_dir>/app.ini` from the running executable and `RfSimulatorApp::~RfSimulatorApp()` writes it, so every app-level test plus each `test_session_state.cpp` case read-modify-write that one file concurrently — unsolved, and the reason `-jN` is not unconditionally safe. `LayoutManager` derives `<exe_dir>/layouts` and `TutorialState` derives `<exe_dir>/.tutorial_completed` with the same sharing, so `test_ui` (`test_engine/CMakeLists.txt`) is `RUN_SERIAL TRUE`: it is the only test that drives all three through the app, while `tests/test_layout_manager.cpp` calls `remove_all(layoutsDir())` and `tests/test_tutorial_state.cpp` removes the marker, and without serialization another test deletes the file `test_ui` is asserting on (reproduced 2026-09-18 by deleting the file under the run: `ui_tests.cpp:657`/`:665` for `layouts/UITestLayout.ini`, which a second concurrent `test_ui` run also hits on its own, and `ui_tests.cpp:778`/`:798` for the marker, which the natural `tests/test_tutorial_state.cpp` pairing did not reproduce in 50 runs). CI never runs `test_ui` (`-E "Benchmark|test_ui"`), so this costs local `-jN` runs only. Concurrent `test_ui` invocations are unsafe in the same way: two at once fail 4/4, with `layout_manage_delete_removes_file` losing the shared `layouts/UITestLayout.ini` and the tutorial cases cascading off the resulting missing menu item.
- **Tests that mutate the built-in extension root must be `RUN_SERIAL TRUE`.** `ExtensionManager` hardcodes `PROJECT_SOURCE_DIR/extensions` as its highest-precedence scan root and every scan enumerates it, so a test writing a manifest there (`test_issue45_extension_trust`, `test_extensions`) is visible to any concurrently running test that counts discovered tools (`test_extensions`). The root is not injectable, so the pair is serialized in `tests/CMakeLists.txt` rather than isolated. `RUN_SERIAL` serializes within one ctest invocation only — a second concurrent `ctest` against the same build tree can still overlap them (observed 2026-09-18) — and it cannot cover a plant left behind by an interrupted run, which fails the next `test_extensions` run with `2 == 1` even when that run is alone. The `ScopedRemove` helpers now report a failed removal through Catch2's bare `WARN(...)` macro (a macro, not a `Catch::` symbol) instead of swallowing the error.

## Work Guidance

- Every DSP engine must have at least a basic correctness test and a dirty/clean benchmark
- Test both nominal and edge cases: zero inputs, max values, parameter extremes
- Node graph tests must verify probe routing, link topology, and topological sort
- Touchstone parser tests must cover all format variants (DB, MA, RI) and frequency units
- Do not depend on ImGui or GLFW in pure DSP-engine tests; app-integration tests **must** create ImGui, ImPlot, and ImNodes contexts (`TEST_CASE_METHOD(ImGuiFixture, ...)`) before constructing `RfSimulatorApp`, which otherwise segfaults headlessly on the Linux/ASan legs.
- App-level tests may include `simulator::app` for integration scenarios

## Verification

- `cmake --build build && ctest --test-dir build` must pass with zero failures
- `ctest --test-dir build -j8` must also pass with zero failures; start it with a clean `extensions/` and never run a second `ctest` against the same build tree at the same time (see Local Contracts)
- `build/bin/tests [bench]` must run benchmarks without crashing
- New test files appear in CTest discovery (`catch_discover_tests`)
