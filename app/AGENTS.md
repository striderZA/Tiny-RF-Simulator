# app/AGENTS.md

## Purpose
Application orchestration and UI for the simulator, including the app-bound project serializer, editor services, component library, instruments, extensions, and agent panel.

## Ownership
- `RfSimulatorApp` is the application orchestrator and owns UI, app state, and widgets; `CircuitRuntime` is UI-free and owns the live graph, components, IDs, topology operations, rewiring, and DSP updates.
- `GraphEditorActions` adapts probe, group, selection, part-number, and group-boundary mutations. `EditorCommands` is the UI-free user-edit entry point; `ProjectSerializer` is app-bound and restores project state through the runtime and editor actions.
- `ComponentRegistry` owns runtime components; `ComponentTypeRegistry` defines component creation, serialization metadata, and inspector dispatch. `simulator::editor_services` is the UI-free boundary for editor services, component library, receiver measurement, and shared output-SNR policy.
- `InspectorPanel` reports parameter edits through `onParamChange`, which marks the project dirty; component-bound views are owned and synchronized by the app.
- `ExtensionManager`, `ExtensionTrustStore`, and `ExternalToolRunner` own extension discovery, trust records, and external-tool execution respectively.
- `ExtensionTrustStore` keys approvals by the weakly canonical extension root, so a copy at another path needs its own approval; the record is `<exe_dir>/extension_trust.json`.
- `TestFlowWidget` is app-owned; flow validation and execution use the UI-free `test_flow` boundary. Network Analyzer and receiver measurement use app-provided scratch graphs; `PowerMeterEngine` measures output power independently of UI.
- `PFBViewManager` owns the per-PFB IQ Plot and Channelizer Grid widgets and their visibility. `clear()` is reserved for bulk engine destruction and runs first in `ProjectSerializer::reset()`, before the engines are destroyed.
- `NetworkAnalyzerEngine` and `NetworkAnalyzerWidget` are a singleton instrument owned by `RfSimulatorApp`. Each measurement runs in a private scratch graph (`NaScratch`, `IsolatedChainRunner`); the reusable `MeasurementChainPath` stays in `network_analyzer_engine`.
- `NaHost` is constructed from the runtime's const `components()` view, so Network Analyzer lookups cannot mutate runtime components through it.
- `ReceiverPerformanceMeasurementEngine` is UI-free and caches output-power and IIP3 measurements over the shared `MeasurementChainPath`. The config and request overloads measure identically.
- `PfbCalculatorWidget` binds M, K, beta, and the rejection target to the selected PFB through the engine setters. All response math comes from `PfbFilterDesign` in `pfb_channelizer/`, so the tool and the engine cannot drift.
- `AppAgentHost` (the app-side `IAgentHost`) owns checkpoints, the activity ring, node placement, modal detection, project-file hooks, and component-library roots. Its Project root is `<current working directory>/rf-sim-libraries`; its Global root is `%USERPROFILE%/.rf-sim/libraries` on Windows or `$HOME/.rf-sim/libraries` otherwise. It does not accept caller-selected paths. `AgentPanelWidget` renders the Agent view and holds only callbacks and the transient selected checkpoint id.
- Checkpoints serialize with `toJson({std::nullopt, false})`; the project name is the current file stem, or none when untitled.
- `ComponentFormModel` and `ComponentFormWidget` are the pure-logic and ImGui pair for the New/Edit Component form.

## Local Contracts
- `RfSimulatorApp::saveProject()` and `loadProject()` return success and delegate to `ProjectSerializer::save()` and `load()`; `newProject()` delegates to `reset()`. A failed load that resets project state clears the save target.
- `ProjectSerializer::save()` stages external RF data and exclusively creates a sibling `<target>.tmp` before writing through that handle and renaming over the target. If creation collides, stale cleanup opens the current regular file at that name; it is not necessarily the entry that caused the collision.
  - Windows deletes the opened stale file through its handle, so a different object swapped in after open is not deleted.
  - POSIX compares the opened descriptor's dev/inode (`fstat`) with the object the name refers to (`lstat`) and unlinks only on a match. A replacement present at the check is refused; a swap between the check and `unlink()` remains a race.
  - Links, folders, and other non-regular entries are refused; stale cleanup fails with a logged reason.
- A failed handle wrap, write, or rename attempts to remove only the temp object this save created, bound to that object's identity. Cleanup is best-effort and may leave the object in place.
  - Windows: the writer omits `FILE_SHARE_DELETE`, so while it is open no handle, including the retained `GENERIC_READ` + `FILE_SHARE_DELETE` handle, can request DELETE. The retained handle does not block the rename. After the writer closes, cleanup reopens it with DELETE and deletes through it, so a replacement at the name survives. If the reopen fails, the temp object is left in place and the failure is logged. A process holding the object without `FILE_SHARE_DELETE` makes the reopen and the rename fail; a holder that shares delete delays removal until it closes.
  - POSIX checks the created descriptor's dev/inode against the name before unlinking. A replacement present at the check survives, but a swap between check and unlink remains a race.
  - Publish is by name. Between the writer close and the rename, nothing protects the name, and the rename publishes whatever holds it then.
- Any failed save preserves the previous project file. The serializer attempts identity-bound removal of the temp object, logs when the Windows reopen fails, and does not remove an unrelated replacement entry (POSIX: the check-to-unlink race above). RF-data rollback in `packageExternalProjectData` removes its files and directories by name and is outside this guarantee.
- `ProjectSerializer::testHooks()` is a test-only seam: fault injection for save-path writes, renames, and stale-entry removal (`failWrite`, `failRename`, `failStaleRemoval`), and observers (`afterStaleOpen`, `beforeFailureCleanup`). Production code never sets it; tests reset it with `testHooks() = {};`.
- Dirty state is derived from the `EditorCommands` revision. Edits outside `EditorCommands` call `markDirty()`; accepted commands advance the revision, probe add and remove included, and rejected commands do not (a duplicate probe add or an absent probe remove is rejected).
- `markClean()` sets the clean point: `saveProject()` calls it only after a successful save (issue #77); `newProject()` and a successful `loadProject()` call it after the serializer runs.
- User-level edits use `EditorCommands`; component-bound views synchronize on component changes. `EditorCommands::setComponentParams()` validates ordered JSON against `ParameterField::state_fields`; top-level and array-element object members are validated in request insertion order, and the first invalid member is returned. Path parameters and read-only, unknown, and type-invalid values are rejected before mutation; enum labels or valid integral indices map to stored indices; arrays replace whole. Accepted edits deserialize within a snapshot/rollback boundary; engine normalization of requested values is rolled back and reported.
- Persisted component parameters and Test Flow conditions use engine `serialize()` keys and encodings. `ParameterField::key` names authoring parameters; `state_fields` names serialized state. Do not rename or re-encode persisted keys without an explicit versioned migration.
- ADC DDC decimation is 1/2/4/8; NCO tuning is stored as a normalized factor of the ADC input sample rate. Legacy ADC state defaults to decimation 2 and NCO +0.25×Fs.
- S-parameter engines fall back to legacy `sparam_path` only when `sparam_filepath` is absent; `sparam_filepath` wins when both exist. A missing `sparam_fwd_idx` selects S21 for a loaded file, as `setSParamFilepath()` does (index 0 when no file is loaded); an explicit index is kept. See `tests/test_sparam_legacy_key.cpp`.
- Data-file path parameters are listed once in `kPathParameterKeys` (`app/include/component_params.h`): `sparam_filepath`, legacy `sparam_path`, `amp_filepath`, and `ampf_filepath`. Project load and library instantiation contain them; project save resolves relative live-engine paths against the process working directory (the engine's load base), relativizes in-project files, and copies external regular, non-symlink files up to 256 MiB each and 512 MiB/256 unique files total into `rf_data/` beside the project. Content-hash names avoid overwrites: an existing regular non-symlink destination with identical bytes is reused; a differing file, symlink, missing/non-regular source, or oversize source fails the save. Copies are reported by `ProjectSerializer::save()` and `RfSimulatorApp::lastSavedDataFiles()`; GUI saves log newly created copies, and `project_save` returns them as `copied_data_files`. Component authoring treats referenced files as in use, and agent/inspector parameter writes reject these keys. `amp_filepath` names a MathWorks AMP file (`amplifier/include/amp_file.h`): its IIP3/OIP3 sections replace the scalar OIP3 while loaded. A failed load keeps the path and error, and the scalar OIP3 applies. `ampf_filepath` names an amp-f v1 file (`amplifier/include/ampf_file.h`); see the amp-f rules below. See `tests/test_path_containment.cpp`, `tests/test_issue79_component_validation.cpp` (library containment), and `tests/test_amplifier_amp_file.cpp`.
- Agent parameter writes (`applyComponentParams`, `app/src/component_params.cpp`) reject a Number outside its state field's `min`/`max` with `TypeMismatch` (`expected` names the range). State-field bounds are declared with `bounded()` in `component_type_registry.cpp`; unbounded fields accept any finite value. Equalizer ref gain is ±40 dB and slope ±100 dB/decade, matching the inspector (`tests/test_component_params.cpp`).
  - When a project references a file outside its folder, `rf_data/` must be a real directory. The save refuses a symbolic link, a Windows reparse point (such as a junction), or an entry whose attributes cannot be read, before it writes through that directory (`isUnverifiedProjectDataDirectory()`). `std::filesystem` reports a junction as an ordinary directory, so the reparse-point check is needed. See the Issue #222 case in `tests/test_path_containment.cpp`.
- AMP intercepts: when a file has both IIP3 and OIP3 sections, the OIP3 section is used and the IIP3 section is ignored (`tests/test_amplifier_amp_file.cpp`).
- amp-f v1 (`ampf_filepath` with `ampf_block`): the block is chosen by its exact VAR and COND values after DEVICE inheritance. A file that fails to load, or a selection that does not match exactly one block, keeps its path and error, and no block is active. OIP3 then comes from a loaded `amp_filepath` file, else the scalar; OIP2 comes from the scalar. An active block replaces the `amp_filepath` intercepts, and a missing value falls back to the scalar. Tests: `tests/test_ampf_file.cpp`, `tests/test_amplifier_ampf.cpp`, `tests/test_nonlinear_frequency_oip2.cpp`.
- The Spectrum Analyzer noise jitter is cosmetic on the noise floor only; deterministic signal tones are never perturbed.
- `sanitizePathSegment()` and `dataFileCopyDestination()` keep component authoring filenames contained; reject destinations that are not bare filenames. `ComponentLibrary` validates definitions against `ComponentTypeRegistry`; ideal filters require `fc_low_Hz` for LPF/HPF and both ordered cutoffs for BPF/BSF. For BPF/BSF, `IdealFilterEngine::isValidCutoffPair()` is the single ordering rule: `setCutoffs_Hz()`, `setFilterType()` and `deserialize()` throw `std::invalid_argument` on low > high, keep the stored band, and `deserialize()` leaves the engine unchanged. The inspector logs and skips the rejected write or Type change; agent writes return `DeserializeFailed` and restore. `ProjectSerializer::fromJson()` refuses a file holding an inverted band before any reset (`load()` and checkpoints alike), so the open project and its save path are kept; it never skips the record, because skipping would drop the filter and its links on the next save. LPF/HPF store `fc_high_Hz` unchecked. An equal pair is accepted (LPF → BPF leaves both at the same value; library validation rejects equal cutoffs, so instances are one step looser by design).
- Extension discovery scans the source-tree built-in root (default `PROJECT_SOURCE_DIR/extensions`; tests may override it with `ExtensionManager::setBuiltInSourceRoot()` before a rescan), executable-relative built-in, global, then project-local roots. The first manifest for an ID wins; later duplicates are `Shadowed`, including when the winner is invalid or incompatible, and are excluded from data packs and external tools.
- Project-local untrusted external tools are absent from the Tools menu and cannot run before approval. External tools run only after the trust gate and under the canonical temporary root `temp/rf-sim-extension-run`.
- `RfSimulatorApp::update_dsp()` pumps `AgentServer` on the UI thread before `CircuitRuntime::update(0.0)`; the listener thread never touches app models or ImGui.
- AgentServer `test_flow_run` uses `FlowRunSession` on the UI thread, advancing at most 64 rows and 6 ms per pump; each row uses the original baseline and restores every engine plus wiring before yielding. It checks epoch and project revision before each slice, aborting without restoring over a replacement or user edit. A restore failure suppresses results and latches the agent tool until project replacement.
- The agent server is opt-in and off at construction; `main()` calls `startAgentServerIfEnabled()` after app construction. `SessionState` persists `[Agent] ServerEnabled` (default false), independently of the `WindowState/Agent` visibility. Enabling stores the opt-in and starts the listener at the endpoint file after `ensurePrivateDirectory()`; disabling stores false and stops the listener. A startup failure keeps the opt-in for retry. `AgentServer` removes its endpoint only while the file still carries its own GUI token.
- `findMeasurementChainPath()` is shared by Network Analyzer and receiver output-power/IIP3 measurements and follows exact linked ports to Point B's selected output, including switched branches rejoining at an RF SPDT 2:1 switch. Combiners, merges fed from outside the measured circuit, and a Point A component that feeds through more than one output port report no data.
- `TestFlowWidget::run()` uses the one-shot `RunFlowWithinBoundary()`: it snapshots every engine before execution, restores each independently by id, and always rewires. A successful run leaves serialized state, links, and revision unchanged and never marks dirty. A restore failure may leave the failing component swept, suppresses the result, and latches until reload. `run()` returns true only for a non-fatal `FlowResult` with complete restoration; invalid individual measurements are normal `N/A` results. A sweep above `kMaxRunRows` is refused before snapshotting.
- `ComponentTypeRegistry` is the component registration path; each registered type must have a matching `NodeKind`/symbol and `InspectorPanel` drawer. Keep registry, creation, serialization, and inspector dispatch consistent.
- Numeric inspector drawers edit a local value and write it back only when changed; preserve untouched fields passed together to a setter. *(The field contract is in the root AGENTS.md.)*
- Receiver requirements are optional project data in the top-level `receiver_requirements` object. Missing data in legacy files means Not configured; malformed objects, fields, or limits are retained as Invalid configuration with a diagnostic and do not abort other project restoration.
- App-level tests must `setStorePath()` to a unique temp file before approving or running a project-local tool; otherwise they write the developer's real `<exe_dir>/extension_trust.json`.
- `ComponentLibrary::loadFile()` / `scan()` continue discovery across malformed files: definitions with valid required fields are retained with malformed optional metadata defaulted. Definitions with missing or wrong-typed required fields, or invalid type-registry parameters, are logged and dropped.
- The Component Library's Refresh button calls `RfSimulatorApp::refreshExtensions()` to rebuild the
  in-memory catalog from current roots; it does not modify the live circuit or its dirty state.
- Component authoring refuses symlink S-parameter destinations and existing files unless the edited definition already references that local asset and no other loaded definition does; new entries never overwrite existing assets. Picked assets and component JSON are staged before commit; if definition replacement fails, the asset update is rolled back, and a rollback failure is shown in the form error.
- `ComponentLibrary::createUserEntry()` accepts only a new authorable definition with registered library fields and no file references. It validates before disk mutation, refuses case-insensitive duplicate `(type, part_number)` pairs and existing destinations, atomically publishes JSON without replacement, then indexes the definition in the live library. Library creation does not modify circuit revision or checkpoints.
- App-level integration tests may use `testExtensionManager()` and `testExtensionResultMessage()` with an ImGui, ImPlot, and ImNodes fixture.
- `computeOutputSnr()` in `simulator::editor_services` owns the shared output measurement rule: PFB output 0 uses active-channel SNR, ENBW, and integrated channel noise; every other available output uses the analyzer's current RBW. `RfSimulatorApp` adapts output 0's optional SNR into node-hover data, and the widget only renders that value.
- Window visibility persists through `SessionState` and `WindowState` keys (for example `WindowState/Agent` and `WindowState/ReceiverRequirements`); Test Flow selection, load state, and the last result are session-only and never persisted.
- The PFB properties inspector reports the active channel's integrated noise power in dBm and its effective noise bandwidth in MHz. This channel-level readout is distinct from the two Spectrum outputs (W/Hz) and their analyzer-RBW-integrated display.
- Project replacement notifications are part of the agent epoch contract: New clears checkpoints and notes `NewProject`; tutorial start notes `Tutorial` after its `newProject()` reset; `loadProject()` clears and notes `OpenedProject` only after success or `lastLoadReset()`, leaving checkpoints untouched after an intact failure.
- `ProjectSerializer::toJson()` / `fromJson()` own in-memory serialization and restoration. `save()` calls `toJson({project_dir, true})`, adds the project name, then retains atomic file output; `load()` retains file reading, the size cap, and parse recovery before calling `fromJson(root, {project_dir, true}, path)`. Without `sparam_root`, S-parameter paths remain verbatim and are not resolved or contained; `window_state=false` omits or ignores window flags for checkpoint snapshots.
- `exitApplication()` stops the agent server before `std::exit(0)`, which skips destructors. Ordinary shutdown stops it in the `RfSimulatorApp` destructor.
- `AppAgentHost` keeps the newest 20 checkpoints and the newest 50 activity entries. Every `recordActivity()` call logs exactly one `Agent:` INFO line, including when the new entry evicts the oldest.
- `AppAgentHost::placeComponents()` honors explicit positions. Automatic placement never moves existing nodes.
- `revertAgentCheckpoint(id)` accepts only a live checkpoint; a missing or stale id is logged, not silently ignored.
- Every IIP3 fundamental and IM3 frequency in `ReceiverPerformanceMeasurementEngine` must stay within the inclusive `MIN_FREQ..MAX_FREQ` bounds.
- `ReceiverRequirementsWidget` stages a draft. Apply validates and commits the entire draft and keeps the view open; Cancel restores the applied snapshot.
- `RfSimulatorApp` declares `ReceiverRequirementsState` before `m_serializer`, so the state outlives the serializer. It declares `AppAgentHost`, `AgentApi`, and `AgentServer` after their dependencies, in that order, so reverse destruction stops the server before its API and host.
- `NaHost` is declared before the two engines constructed with it (`ReceiverPerformanceMeasurementEngine`, `NetworkAnalyzerEngine`), so it outlives both.
- `EditorCommands::swapLibraryPart()` (issue #200) replaces a placed component in place. Compatibility is decided by ports and the physical `graphLinkAllowed()` policy only: the command checks neither component type nor whether the predecessor has a library `part_number`, and the Properties dropdown offers library parts only. The successor keeps the predecessor's component id, so labels, Test Flow references, and agent ids stay valid, and it gets new graph node and pin ids. A link, probe, or `instrument_pins` entry on a port the new part lacks, or a link the policy forbids, refuses the swap with the reason and leaves the circuit and project revision unchanged. An accepted swap detaches the old links, reattaches them by port index, moves probes and group membership through `GraphEditorActions::replaceNodeReferences()`, and only then retires the predecessor; a failed connect rolls back. Parameters come from the new part's library definition, as a fresh placement would.
- The Properties panel's **Part** dropdown (`InspectorPanel::drawPartPicker()`) appears for components with a library `part_number` and lists every library definition. It defers the swap to the end of `draw()`, because a swap deletes the engine the drawers use. `RfSimulatorApp::swapLibraryPart()` moves the canvas position, selects the successor, remaps the Network Analyzer Point A/B and Power Meter source pins, and carries a PFB's in-session IQ Plot and Channelizer Grid visibility to the successor. `PFBViewManager` keys its views by graph node id and the successor has a new one, so the app copies the flags across explicitly; `SessionState` is not used because it persists only on Windows.
- `Help > Tutorial` and the first-run "Welcome" modal both route through `requestTutorial()`, which runs the same `PendingAction`/unsaved-changes guard as New/Open/Exit (`PendingAction::Tutorial`) before `startTutorial()` resets to a seeded sandbox. Any new `PendingAction` value must be handled in both the Save and Discard branches of that modal.
- The POSIX launch (`launchProcess` in `external_tool_runner.cpp`) prepares everything in the parent before `fork()`: argv text, the PATH candidate list for a bare command name (`python3` for `.py` entries, read from the parent's PATH), and an envp pointer array over the environment at fork time. The child is restricted to async-signal-safe calls (`setpgid`, `chdir`, `execve`, `_exit`) and reads `errno`; it allocates nothing, and its only write of its own is the preallocated `shell_argv[1]` slot, set before the `/bin/sh` fallback for files without a shebang. The search is not an exact `execvp()` replica: it continues past `EACCES`, `ENOENT`, and `ENOTDIR`, any other errno stops it, and no runnable candidate exits 127. Windows keeps its suspended-process job-object launch.
- Per-PFB IQ Plot / Channelizer Grid window visibility lives in `PFBViewManager::iqVisibility()`/`gridVisibility()` (indexed in lockstep with the manager's widgets, in registry order) and has no View-menu entry since instances are dynamic; closed windows are reopened via "Show IQ Plot"/"Show Channelizer Grid" checkboxes in the PFB properties panel, wired each frame through `InspectorPanel::setPFBWindowVisibility()` (stores the stable vector pointers, not element pointers, since `sync()` replaces the vectors on every component-set change)
- Receiver Requirements is a separate `View > Receiver Requirements` singleton dockable view; visibility persists as `WindowState/ReceiverRequirements`, while the band and optional metric limits/conditions are project data persisted by `ProjectSerializer`. `RfSimulatorApp` updates the Network Analyzer exactly once per frame whenever either instrument view is visible, so Requirements-only visibility refreshes the shared Point A/B sweep. While Requirements is visible, the app obtains tone options only from the component at Point A (only generators expose choices), calls the app-owned receiver engine with applied requirements and analyzer sweep, then passes its partial/full output-power and IIP3 vectors plus current gain/NF vectors to the evaluator and widget. The engine advances at most 4 ms of scratch-stimulus work per visible frame; closing Requirements pauses it without discarding same-request progress, and reopening resumes it. A changed request signature resets pending work. The signature holds only measured inputs: Point A/B, the sweep grid, which metrics are enabled, the enabled metric's tone selector or IIP3 conditions, and the measured path's signature (every path component's state, including Point A's generator, and the links between them). Pass/fail limits, band edges, a disabled metric's conditions, and links off the measured path keep cached samples; the evaluator re-checks them against the retained samples each frame. A lone Point A tone may be preselected; multiple tones require explicit selection. A missing, stale, or frequency-ambiguous selector stays Incomplete with no fallback. Applied requirement/source-tone changes mark the project dirty. Outcomes are Not configured, Invalid configuration, Incomplete, Pass, or Fail; only complete valid configured requirements can Pass (green), Fail is red, and all other tones are neutral. Draft edits show neutral `Unapplied edits`, never a stale Pass/Fail.
- The Filter Calculator window is toggled by `View > Filter Calculator` (`m_show_calculator`, persisted through `SessionState` `WindowState`/`FilterCalculator`); its design/metrics cache is rebuilt only after the control being dragged/typed releases (`IsAnyItemActive` gate), since a full resynthesis costs seconds at worst-case M=2048/K=64
- `CircuitRuntime::epoch()` starts at zero, advances exactly once at the end of each `clearComponentsAndResetIds()` call, and does not change for ordinary component or link edits.
- A condition whose `path` does not resolve is marked red and answered with `path_hints` — up to `kMaxPathHints` sweepable keys from that engine — because a mistyped `serialize()` key (never an inspector label) is the likeliest authoring mistake.
