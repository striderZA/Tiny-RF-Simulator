# app/AGENTS.md

## Purpose
Application orchestration and UI for the simulator, including the app-bound project serializer, editor services, component library, instruments, extensions, and agent panel.

## Ownership
- `RfSimulatorApp` is the application orchestrator and owns UI, app state, and widgets; `CircuitRuntime` is UI-free and owns the live graph, components, IDs, topology operations, rewiring, and DSP updates.
- `GraphEditorActions` adapts probe, group, selection, part-number, and group-boundary mutations. `EditorCommands` is the UI-free user-edit entry point; `EditorHistory` holds its undo/redo records (a linear stack of snapshot deltas); `ProjectSerializer` is app-bound and restores project state through the runtime and editor actions.
- `ComponentRegistry` owns runtime components; `ComponentTypeRegistry` defines component creation, serialization metadata, and inspector dispatch. `simulator::editor_services` is the UI-free boundary for editor services, component library, receiver measurement, and shared output-SNR policy.
- `InspectorPanel` reports parameter edits through `onParamChange`, which marks the project dirty; component-bound views are owned and synchronized by the app.
- `rf_view_ui.h` holds the shared presentation primitives (status badges, section headers, hints, reserved lines) for the Receiver Requirements and RF Budget views. They are non-interactive and submit no focusable item.
- `ExtensionManager`, `ExtensionTrustStore`, and `ExternalToolRunner` own extension discovery, trust records, and external-tool execution respectively.
- `ExtensionTrustStore` keys approvals by the weakly canonical extension root, so a copy at another path needs its own approval; the record is `<exe_dir>/extension_trust.json`.
- `TestFlowWidget` is app-owned; flow validation and execution use the UI-free `test_flow` boundary. Network Analyzer and receiver measurement use app-provided scratch graphs; `PowerMeterEngine` measures output power independently of UI.
- `PFBViewManager` owns the per-PFB IQ Plot and Channelizer Grid widgets and their visibility. `clear()` is reserved for bulk engine destruction and runs first in `ProjectSerializer::reset()`, before the engines are destroyed.
- `NetworkAnalyzerEngine` and `NetworkAnalyzerWidget` are a singleton instrument owned by `RfSimulatorApp`. Each measurement runs in a private scratch graph (`NaScratch`, `IsolatedChainRunner`); the reusable `MeasurementChainPath` stays in `network_analyzer_engine`.
- `NaHost` is constructed from the runtime's const `components()` view, so Network Analyzer lookups cannot mutate runtime components through it.
- `ReceiverPerformanceMeasurementEngine` is UI-free and caches output-power and IIP3 measurements over the shared `MeasurementChainPath`. The config and request overloads measure identically.
- `PfbCalculatorWidget` binds M, K, beta, and the rejection target to the selected PFB through the engine setters. All response math comes from `PfbFilterDesign` in `pfb_channelizer/`, so the tool and the engine cannot drift.
- `AppAgentHost` (the app-side `IAgentHost`) owns checkpoints, the activity ring, node placement, modal detection, project-file hooks, receiver-requirements and RF-budget hooks, and component-library roots. Its Project root is `<current working directory>/rf-sim-libraries`; its Global root is `%USERPROFILE%/.rf-sim/libraries` on Windows or `$HOME/.rf-sim/libraries` otherwise. It does not accept caller-selected paths. `AgentPanelWidget` renders the Agent view and holds only callbacks and the transient selected checkpoint id.
- Checkpoints serialize with `toJson({std::nullopt, false})`; the project name is the current file stem, or none when untitled.
- `ComponentFormModel` and `ComponentFormWidget` are the pure-logic and ImGui pair for the New/Edit Component form.
- `ui_font_model` (`app/include/ui_font_model.h`, UI-free, `simulator::ui_font_model`) owns the Settings font picker rules: the monospaced-only, loadable, one-per-family, case-insensitive sorted list; each family's drawn faces (`familyFaces()`: one row per distinct file content, so identical copies and an oblique copy of the upright bytes are one row; a variable file's row takes the weight of its fvar default instance, and a static file keeps the platform's name; upright first, each by ascending weight; a repeated name is labelled by its weight); the face plan for a base family, style, and emphasis (`planFaces()`: the body face matched by name and then by weight and slant, the Bold or Medium emphasis face, and a note for each fallback); the saved family, size, and emphasis resolution; and the platform reads (`ui_font_system_windows.cpp` lists the families through GDI and each family's faces through DirectWrite, `ui_font_system_fontconfig.cpp` through fontconfig with `FC_SPACING = FC_MONO`, `ui_font_system_none.cpp` elsewhere).
- `UiFontController` (`app/include/ui_font_controller.h`) owns the UI font choice (base family, style, emphasis, and size), keeps the saved choice apart from the applied one, and installs the body and emphasis fonts into the ImGui atlas; `SettingsPanelWidget` (`settings_panel_widget.h`) draws the `Settings > UI Font...` window (family list, Style, emphasis, Font size, Preview) and only presents the controller's state.

## Local Contracts
- `RfSimulatorApp::saveProject()` and `loadProject()` return success and delegate to `ProjectSerializer::save()` and `load()`; `newProject()` delegates to `reset()`. A failed load that resets project state clears the save target.
- `ProjectSerializer::save()` stages external RF data and exclusively creates a sibling `<target>.tmp` before writing through that handle and renaming over the target. If creation collides, stale cleanup opens the current regular file at that name; it is not necessarily the entry that caused the collision.
  - Windows deletes the opened stale file through its handle, so a different object swapped in after open is not deleted.
  - POSIX compares the opened descriptor's dev/inode (`fstat`) with the object the name refers to (`lstat`) and unlinks only on a match. A replacement present at the check is refused; a swap between the check and `unlink()` remains a race.
  - Links, folders, and other non-regular entries are refused; stale cleanup fails with a logged reason.
- A failed handle wrap, write, or rename attempts to remove only the temp object this save created, bound to that object's identity. Cleanup is best-effort and may leave the object in place.
  - Windows: the writer omits `FILE_SHARE_DELETE`, so while it is open no handle, including the retained `GENERIC_READ` + `FILE_SHARE_DELETE` handle, can request DELETE. The retained handle does not block the rename. After the writer closes, cleanup reopens it with DELETE and deletes through it, so a replacement at the name survives. If the reopen fails, the temp object is left in place and the failure is logged. A process holding the object without `FILE_SHARE_DELETE` makes the reopen and the rename fail; a holder that shares delete delays removal until it closes.
  - POSIX checks the created descriptor's dev/inode against the name before unlinking. A replacement present at the check survives, but a swap between check and unlink remains a race.
  - Publish is by name. Between the writer close and the rename, nothing protects the name, and the rename publishes whatever holds it then.
- Any failed save preserves the previous project file. The serializer attempts identity-bound removal of the temp object, logs when the Windows reopen fails, and does not remove an unrelated replacement entry (POSIX: the check-to-unlink race above). RF-data rollback in `packageExternalProjectData` removes its files and directories by name and is outside this guarantee.
- `ProjectSerializer::testHooks()` is a test-only seam: fault injection for save-path writes, renames, and stale-entry removal (`failWrite`, `failRename`, `failStaleRemoval`), and observers (`afterStaleOpen`, `beforeFailureCleanup`). Production code never sets it; tests reset it with `testHooks() = {};`.
- Dirty state is derived from the `EditorCommands` revision. Edits outside `EditorCommands` call `markDirty()`; accepted commands advance the revision, probe add and remove included, and rejected commands do not (a duplicate probe add or an absent probe remove is rejected). Widget parameter edits call `markDirty()` and record through `noteWidgetEdit()`/`flushWidgetEdit()`, which commit one record once the control is released (`IsAnyItemActive()` false).
- Undo and redo are deltas between `EditorSnapshot`s: components keyed by graph node id, links by pin pair, probe slots in order, groups, grid-space (pan-independent) node positions, and app state. Undo and redo restore a removed component under its original component, graph node, and pin ids (and a group under its id); links are matched by pin pair because a redo reallocates link ids. Each changed key applies only where the current value still equals the side it replaces (the record's `before` for redo, its `after` for undo), so a key edited since the record is left alone. Depth is `EditorHistory::kMaxRecords` (100), a push after an undo drops the redo stack, and a canvas delete (its nodes and links together), a library-part swap, a duplicate, and one agent tool call (`Agent: <tool>`) each record as one delta through a nested edit group.
- `clearHistory()` starts the history over on New, a replacing load, a failed load that reset state, and a checkpoint revert, because those replace the engines and reuse node ids. Undo and redo advance the revision (so the project is dirty) and never change the runtime epoch; the epoch advances only in `CircuitRuntime::clearComponentsAndResetIds()`.
- App-state keys are `receiver_requirements` (the per-mode `selected_mode` is view state and excluded), `rf_budget`, and `na_points`; undo and redo apply each only while it still holds the recorded value.
- `markClean()` sets the clean point: `saveProject()` calls it only after a successful save (issue #77); `newProject()` and a successful `loadProject()` call it after the serializer runs.
- User-level edits use `EditorCommands`; component-bound views synchronize on component changes. `EditorCommands::setComponentParams()` validates ordered JSON against `ParameterField::state_fields`; top-level and array-element object members are validated in request insertion order, and the first invalid member is returned. Path parameters and read-only, unknown, and type-invalid values are rejected before mutation; enum labels or valid integral indices map to stored indices; arrays replace whole. Accepted edits deserialize within a snapshot/rollback boundary; engine normalization of requested values is rolled back and reported.
- Persisted component parameters and Test Flow conditions use engine `serialize()` keys and encodings. `ParameterField::key` names authoring parameters; `state_fields` names serialized state. Do not rename or re-encode persisted keys without an explicit versioned migration.
- ADC DDC decimation is 1/2/4/8; NCO tuning is stored as a normalized factor of the ADC input sample rate. Legacy ADC state defaults to decimation 2 and NCO +0.25×Fs.
- S-parameter engines fall back to legacy `sparam_path` only when `sparam_filepath` is absent; `sparam_filepath` wins when both exist. A missing `sparam_fwd_idx` selects S21 for a loaded file, as `setSParamFilepath()` does (index 0 when no file is loaded); an explicit index is kept, unless it is outside the loaded matrix `[0, N²)`: then it falls back to S21 with a warning, so an agent write of that index returns `ENGINE_ADJUSTED` and rolls back. See `tests/test_sparam_legacy_key.cpp` and `tests/test_component_params.cpp`.
- Data-file path parameters are listed once in `kPathParameterKeys` (`app/include/component_params.h`): `sparam_filepath`, legacy `sparam_path`, `amp_filepath`, and `ampf_filepath`. Project load and library instantiation contain them; project save resolves relative live-engine paths against the process working directory (the engine's load base), relativizes in-project files, and copies external regular, non-symlink files up to 256 MiB each and 512 MiB/256 unique files total into `rf_data/` beside the project. Content-hash names avoid overwrites: an existing regular non-symlink destination with identical bytes is reused; a differing file, symlink, missing/non-regular source, or oversize source fails the save. Copies are reported by `ProjectSerializer::save()` and `RfSimulatorApp::lastSavedDataFiles()`; GUI saves log newly created copies, and `project_save` returns them as `copied_data_files`. Component authoring treats referenced files as in use, and agent/inspector parameter writes reject these keys. `amp_filepath` names a MathWorks AMP file (`amplifier/include/amp_file.h`): its IIP3/OIP3 sections replace the scalar OIP3 while loaded. A failed load keeps the path and error, and the scalar OIP3 applies. `ampf_filepath` names an amp-f v1 file (`amplifier/include/ampf_file.h`); see the amp-f rules below. See `tests/test_path_containment.cpp`, `tests/test_issue79_component_validation.cpp` (library containment), and `tests/test_amplifier_amp_file.cpp`.
- `ComponentLibrary::applyDefinition()` applies a library part's parameters and data files as `instantiate()` does, and returns one sentence per declared file that is rejected or does not load (outside the library folder, no library folder, S-parameter or AMP or amp-f file not loaded). `instantiate()` ignores the sentences, so a part with a missing file still instantiates (`tests/test_component_library_load_status.cpp`).
- Agent parameter writes (`applyComponentParams`, `app/src/component_params.cpp`) reject a Number outside its state field's `min`/`max` with `TypeMismatch` (`expected` names the range). State-field bounds are declared with `bounded()` in `component_type_registry.cpp`; unbounded fields accept any finite value. Equalizer agent writes use the inspector ranges: ref gain ±40 dB, ref frequency 1 Hz–100 GHz, slope ±100 dB/decade (`tests/test_component_params.cpp`). Library validation keeps the registry `fields` ranges (ref gain ±50, ref frequency 0–1e12), so a library entry can pass validation and still be refused by an agent write.
  - Digital step attenuator writes are bounded the same way: bit depth 1–16, step 0–20 dB, ref insertion loss 0–30 dB, and code 0–65535. A `code` above the live `2^bit_depth − 1` is an engine adjustment: the write rolls back and reports `ENGINE_ADJUSTED` (the `sparam_fwd_idx` precedent); shrinking `bit_depth` applies and reports the re-clamped code as an engine-side change (`tests/test_component_params.cpp`).
  - When a project references a file outside its folder, `rf_data/` must be a real directory. The save refuses a symbolic link, a Windows reparse point (such as a junction), or an entry whose attributes cannot be read, before it writes through that directory (`isUnverifiedProjectDataDirectory()`). `std::filesystem` reports a junction as an ordinary directory, so the reparse-point check is needed. See the Issue #222 case in `tests/test_path_containment.cpp`.
- AMP intercepts: when a file has both IIP3 and OIP3 sections, the OIP3 section is used and the IIP3 section is ignored (`tests/test_amplifier_amp_file.cpp`). `AmplifierEngine::oip3At_Hz()` returns the OIP3 `update()` applies at a frequency, with `covered` and `reason`. It is uncovered outside the section's band (the edge value is held), outside the S-parameter band for an IIP3 section in S-parameter mode, or when the derived value is not finite (`tests/test_amplifier_intercept_coverage.cpp`).
- amp-f v1 (`ampf_filepath` with `ampf_block`): the block is chosen by its exact VAR and COND values after DEVICE inheritance. A file that fails to load, or a selection that does not match exactly one block, keeps its path and error, and no block is active. OIP3 then comes from a loaded `amp_filepath` file, else the scalar; OIP2 comes from the scalar. An active block replaces the `amp_filepath` intercepts. A missing value falls to the next finite source in the order OIP3, IIP3 plus gain, OP1dB plus the P1dB offset, IP1dB plus gain plus that offset, then the scalar. `oip3At_Hz()` reports the chosen source uncovered outside the block's rows, outside the S-parameter band for a gain-derived source in S-parameter mode, and reports the scalar uncovered when no source is finite. Tests: `tests/test_ampf_file.cpp`, `tests/test_amplifier_ampf.cpp`, `tests/test_nonlinear_frequency_oip2.cpp`, `tests/test_amplifier_intercept_coverage.cpp`.
- The Spectrum Analyzer noise jitter is cosmetic on the displayed noise floor only; deterministic signal tones are never perturbed. Peak and marker readouts use `renderCombinedReadoutSpectrum()` (jitter-free) so their values are not biased or frame-variant; the plotted trace stays jittered.
- `sanitizePathSegment()` and `dataFileCopyDestination()` keep component authoring filenames contained; reject destinations that are not bare filenames. `ComponentLibrary` validates definitions against `ComponentTypeRegistry`; ideal filters require `fc_low_Hz` for LPF/HPF and both ordered cutoffs for BPF/BSF. For BPF/BSF, `IdealFilterEngine::isValidCutoffPair()` is the single ordering rule: `setCutoffs_Hz()`, `setFilterType()` and `deserialize()` throw `std::invalid_argument` on low > high, keep the stored band, and `deserialize()` leaves the engine unchanged. The inspector logs and skips the rejected write or Type change; agent writes return `DeserializeFailed` and restore. `ProjectSerializer::fromJson()` refuses a file holding an inverted band before any reset (`load()` and checkpoints alike), so the open project and its save path are kept; it never skips the record, because skipping would drop the filter and its links on the next save. LPF/HPF store `fc_high_Hz` unchecked. An equal pair is accepted (LPF → BPF leaves both at the same value; library validation rejects equal cutoffs, so instances are one step looser by design).
- Extension discovery scans the source-tree built-in root (default `PROJECT_SOURCE_DIR/extensions`; tests may override it with `ExtensionManager::setBuiltInSourceRoot()` before a rescan), executable-relative built-in, global, then project-local roots. The first manifest for an ID wins; later duplicates are `Shadowed`, including when the winner is invalid or incompatible, and are excluded from data packs and external tools.
- Project-local untrusted external tools are absent from the Tools menu and cannot run before approval. External tools run only after the trust gate and under the canonical temporary root `temp/rf-sim-extension-run`.
- `RfSimulatorApp::update_dsp()` pumps `AgentServer` on the UI thread before `CircuitRuntime::update(0.0)`; the listener thread never touches app models or ImGui.
- AgentServer `test_flow_run` uses `FlowRunSession` on the UI thread, advancing at most 64 rows and 6 ms per pump; each row uses the original baseline and restores every engine plus wiring before yielding. It checks epoch and project revision before each slice, aborting without restoring over a replacement or user edit. A restore failure suppresses results and latches the agent tool until project replacement.
- The agent server is opt-in and off at construction; `main()` calls `startAgentServerIfEnabled()` after app construction. `SessionState` persists `[Agent] ServerEnabled` (default false), independently of the `WindowState/Agent` visibility. Enabling stores the opt-in and starts the listener at the endpoint file after `ensurePrivateDirectory()`; disabling stores false and stops the listener. A startup failure keeps the opt-in for retry. `AgentServer` removes its endpoint only while the file still carries its own GUI token.
- `findMeasurementChainPath()` is shared by Network Analyzer and receiver output-power/IIP3 measurements and follows exact linked ports to Point B's selected output, including switched branches rejoining at an RF SPDT 2:1 switch. Combiners, merges fed from outside the measured circuit, and a Point A component that feeds through more than one output port report no data.
- `TestFlowWidget::run()` uses the one-shot `RunFlowWithinBoundary()`: it snapshots every engine before execution, restores each independently by id, and always rewires. A successful run leaves serialized state, links, and revision unchanged and never marks dirty. A restore failure may leave the failing component swept, suppresses the result, and latches until reload. `run()` returns true only for a non-fatal `FlowResult` with complete restoration; invalid individual measurements are normal `N/A` results. A sweep above `kMaxRunRows` is refused before snapshotting.
- `ComponentTypeRegistry` is the component registration path; each registered type must have a matching `NodeKind`/symbol and `InspectorPanel` drawer. Keep registry, creation, serialization, and inspector dispatch consistent.
- Numeric inspector drawers edit a local value and write it back only when changed; preserve untouched fields passed together to a setter. *(The field contract is in the root AGENTS.md.)*
- Receiver requirements are optional format-3 project data in the top-level `receiver_requirements` object: named modes with a stable `id` and an optional config each, the `next_mode_id` counter, and the selected mode. Ids are assigned once and never reused within a project. Format 2 and a legacy single object (no `format` key) load with ids `1..n`; an empty set writes no key unless its counter is above 1. On load the counter is also raised above every `rf_budget` record's mode id, so no id a record names is reissued. Malformed objects, fields, or limits are retained as Invalid configuration with a diagnostic and do not abort other project restoration. A config may carry up to 16 `oob_suppression` points anchored to `band_start_hz` or `band_stop_hz`; each resolves to a positive frequency outside the band, needs gain limits, and its budget verdict fails when the cascade gain there exceeds `gain_min_db - min_db`. The live Requirements measurement ignores these points.
- Format-3 `snr` (`{min_db, bandwidth_hz}`) is a mode limit judged only by the RF budget cascade: the output SNR is the input level minus kTB at `bandwidth_hz` (`common.h` k and T) minus the cumulative NF, so gain cancels. It is worst-case over the band and is reported beside gain, NF, output power, and IIP3 in the Requirements and RF Budget verdicts. No input level leaves it Incomplete. The measured Requirements view has no SNR series, so its SNR row stays Incomplete.
- The RF budget is optional format-1 project data in the top-level `rf_budget` object (`app/include/rf_budget.h`, `app/src/rf_budget.cpp`, UI-free in `simulator::editor_services`): one point count, a stage table (name, type, library part or idealized params, one feed per input port), named `(stage, port)` outputs, and per-requirements-mode-id overrides. The budget owns stages, topology, per-mode stage settings, and the point count; it reads requirements only for the mode ids its records key on, so a removed mode's record is kept and reported as orphaned. An empty budget writes no key; malformed data is retained as Invalid configuration with a diagnostic that never aborts the rest of the load, and `reset()` clears it. A well-formed table that `validateRfBudget()` refuses loads intact, so a budget built in steps survives a reload and save; `rfBudgetFromJson()` refuses only shape errors, the view shows the live refusal and can discard a retained invalid marker, and the agent `budget_edit` validates after decoding. `validateRfBudget()` is the single refusal rule (limits, names, source fields, feeds, topology, outputs, mode records) and names the offending stage, output, or port.
- `rf_budget_stage` (`app/include/rf_budget_stage.h`, `app/src/rf_budget_stage.cpp`, UI-free in `simulator::editor_services`) evaluates one budget stage as a real engine in a private scratch graph (`NodeGraphEngine` + `ViewManager` + `ComponentRegistry`, as `NaScratch` is) and drives it with the Network Analyzer's own `sweepStimulus` comb at −30 dBm on one input port. A library stage matches by type plus case-insensitive part number and is configured through `ComponentLibrary::applyDefinition()`; any issue it reports refuses the stage. An idealized stage's params, then the mode record's overrides, are written through `applyComponentParams()`; the first refusal names the stage or the `stage.key` override and uses `paramWriteMessage()`. An amplifier's `enableNonlinear()` is recorded when the engine is built and switched off for the comb, so gain and NF carry no compression while `AmplifierEngine::oip3At_Hz()` still reports OIP3 (an uncovered point is NaN with its reason); every other type is +inf and linear. Per point and port, a flagged tone or bin is NaN with the S-parameter reason, a missing tone is −inf gain and +inf NF with the no-transmission reason, and an undefined NF is NaN with its reason. Engines are cached by stage name and overrides, so one evaluator serves every mode. `checkRfBudgetParams()` reports the first refused idealized params or override as a JSON pointer.
- `rf_budget_cascade` (`app/include/rf_budget_cascade.h`, `app/src/rf_budget_cascade.cpp`, UI-free in `simulator::editor_services`) routes a mode's record through the stage fed by the budget input (splitter: every output; `rf_switch_spdt`: `active_throw`; `rf_switch_spdt_2to1`: output 0 only when entered on the active input; other types: output 0) and evaluates one cascade per reached output on `linearSweepFrequencies(band, point_count)`, with one `RfBudgetStageEvaluator` shared by every mode and output. Completeness is per quantity: a stage that passes no signal (−inf gain) keeps cumulative gain, NF (+inf), level (−inf), and later headroom (+inf) infinite with its no-transmission reason, never NaN; a NaN input leaves only the quantities that need it NaN with the first missing input's reason (stage order, then gain, NF, OIP3); NF share uses the finished path total and reports "The path adds no noise." when it is 1. A path with no nonlinear stage has +inf input-referred IIP3 and its verdict is Incomplete with "No nonlinear stage on the path; IIP3 cannot be measured." Headroom is `outputLevelForCompression_dBm(OIP3, 1) − level`, NaN with the stage's OIP3 reason when the stage is linear. Every output not reached names its switch ("Switch 'SW' selects T2 in this mode." or "Switch 'SW' could not be evaluated."). Verdicts come from `evaluateReceiverRequirements()` against the mode's own config; budget records whose id no requirements mode has are reported in `orphaned_mode_ids` (`tests/test_rf_budget_cascade.cpp`). Each configured out-of-band suppression point is appended to the grid exactly, and the verdict judges the unfloored cumulative gain there.
- Budget readouts follow the Network Analyzer's -100 dB floor: a finite cumulative gain below -100 dB publishes no value for cumulative gain, NF, level, and headroom, and the reason names the stage output. The Friis and IIP3 running sums keep the true gain, so a later stage can recover. IIP3 is input-referred and is not floored.
- Verdicts judge the unfloored cumulative values, so a chain below -100 dB still fails a gain minimum. `floorRfBudgetReadouts()` blanks only the published readouts.
- RF budget stage references (feeds, outputs, and mode override keys) match stage names exactly, case included, in `validateRfBudget()` and the cascade walk; stage names stay unique case-insensitively. A blocked route does not claim an output: an output is reported unreached only when no live route reaches it, and then with the first blocked reason.
- `addRfBudgetStage()`, `renameRfBudgetStage()`, `removeRfBudgetStage()`, `setRfBudgetStageType()`, `addRfBudgetOutput()`, `renameRfBudgetOutput()`, `removeRfBudgetOutput()`, and the mode-record/override helpers in `rf_budget.cpp` own table mutations. A rename rewrites every feed, output, and mode override key; an output rename validates its name like a stage rename; a removal unfeds consumers and drops outputs and overrides that name the stage; a type change keeps the feeds that still fit, unfeds consumers of a vanished output port, drops outputs on a vanished port, erases the stage's per-mode overrides, and clears `params`/`part_number`. Refusals leave the model unchanged.
- `RfBudgetWidget` (`app/include/rf_budget_widget.h`, `app/src/rf_budget_widget.cpp`) is the `View > RF Budget` editor: a horizontal signal-chain strip (`budget_chain`) of bordered child-window blocks — the budget input block on the left, one compact block per stage in table order (elided name, type combo, source combo with the part picker or idealized **Params...** editor, one feed combo per input port, rename/remove), the outputs block on the right — joined by draw-list flow arrows drawn at the source block's mid-height. Blocks keep fixed widths; a dock narrower than the chain scrolls the strip horizontally, and a block scrolled out of view is culled but still records its layout rect. There is no feeds modal: the feed combos are inline, and an unfed port's preview is drawn in the warning color. It records the rects of its interactive items (`lastItemRects()`, the `TestFlowWidget::lastButtonRects()` pattern) because a headless frame has no label-based item lookup. Below the strip: per-mode overrides (mode combo, Budgeted/Not-budgeted tag, and the record action on one row), a per-output verdict strip, ImPlot gain/NF sweeps with the selected mode's requirement limits (side by side above ~760 px of width, stacked below), then two collapsible detail sections: the worst-case-over-band table (open by default) and the per-frequency cascade table with the interned reason in the cell tooltip (closed by default). Plot height follows the remaining window height, clamped to 140-240 px. It edits the model in place, calls `onChange` for every accepted change, and keeps its selections and modal drafts session-only. A modal owns each rename/params draft so a table row never edits a `std::string` in place. The status line shows a retained invalid marker first (with **Discard invalid budget**), then the empty hint, then the live validation refusal. **Budget this mode** creates an empty mode record (and **Clear budget record** removes it once its overrides are gone), because `evaluateRfBudget()` reports a mode without a record as `NotBudgeted`. **Add override** is disabled when the selected setting already has an override and clamps its initial value into the field's range. The mode selectors open on `ReceiverRequirementsSet::selected` and follow a Requirements-view selection change.
- `RfSimulatorApp` caches `RfBudgetEvaluation` and reruns `evaluateRfBudget()` only while `m_rf_budget_evaluation_dirty` is set or the library revision changed. The dirty flag is set by either widget's `onChange`, the agent budget/requirements hooks, `refreshExtensions()`, and project replacement through those paths; `revertAgentCheckpoint()` calls `refreshExtensions()` after the restore. The Requirements view draws a Budget prediction table from the selected mode's `RfBudgetModeResult` (coloured independently of the measured status), including unreached outputs; when the evaluation produced no mode results, it shows `not_evaluated_reason` instead of claiming the mode is unbudgeted.
- App-level tests must `setStorePath()` to a unique temp file before approving or running a project-local tool; otherwise they write the developer's real `<exe_dir>/extension_trust.json`.
- `ComponentLibrary::loadFile()` / `scan()` continue discovery across malformed files: definitions with valid required fields are retained with malformed optional metadata defaulted. Definitions with missing or wrong-typed required fields, or invalid type-registry parameters, are logged and dropped.
- The Component Library's Refresh button calls `RfSimulatorApp::refreshExtensions()` to rebuild the

- Font enumeration accepts only single-face TrueType or OpenType (`isSingleFaceFontFile`): font collections and bitmap fonts are refused. Fontconfig still matches faces by family, weight, and slant, so a face it cannot resolve to that exact request is refused.
